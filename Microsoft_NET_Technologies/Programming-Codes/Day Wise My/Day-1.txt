--CLR and JIT Compiling

C# , like Java, is executed indirectly through an abstract computer architecture called the CLR.
The CLR is a virtual machine that runs the code on the computer.
The CLR is responsible for loading the code, checking for errors, and executing the code.
The CLR is also responsible for memory management, which means it handles the allocation and deallocation of memory
The CLR is also responsible for security, which means it checks the code for any potential security threats.
The CLR is also responsible for garbage collection, which means it automatically frees up memory that is no longer needed.

All .NET language compile to the same CIL (Common Intermediate Language)
Each language actually uses only a subset of the CIL (Common Intermediate Language)
The Least-common denominator is the Common Language Specification (CLS)
So, if you want to use your C# components in VB you need to program to the CLS 

--CLR v/s CLI 

CLR is actually an implementation by Microsoft of the CLI (Common Language Infrastructure)
CLI is the specification that defines the common language runtime and the common type system
CLI is an open specification
CLR is really a platform specific implementation

--The CLR architecture

CLR Architecture Overview

    Execution Engine:
        The execution engine is responsible for executing the Common Intermediate Language (CIL) code. It includes:
            Just-In-Time (JIT) Compiler: Converts CIL to native machine code at runtime. The JIT compiler optimizes the code for performance.
            Garbage Collector (GC): Manages memory allocation and deallocation. It automatically frees up memory that is no longer in use, helping to prevent memory leaks.
            Code Manager: Manages the execution of the code, including loading and unloading assemblies.

    Type System:
        The CLR provides a unified type system that allows different .NET languages to interact with each other. All types in .NET derive from a common base class, System.Object, which ensures that objects from different languages can be used interchangeably.

    Memory Management:
        The CLR handles memory allocation and deallocation through the garbage collector. It automatically manages the lifecycle of objects, reclaiming memory that is no longer needed.

    Security:
        The CLR provides a security model that includes code access security (CAS) and role-based security. It ensures that applications have the necessary permissions to execute and access resources.

    Exception Handling:
        The CLR provides a structured exception handling model that allows developers to handle errors gracefully. It supports try-catch-finally blocks for managing exceptions.

    Interoperability:
        The CLR allows .NET applications to interact with other technologies and languages, such as COM (Component Object Model) and native Windows APIs. This is achieved through Platform Invocation Services (P/Invoke) and COM Interop.

    Assembly and Metadata:
        Assemblies are the building blocks of .NET applications. They contain compiled code (CIL), resources, and metadata. The CLR uses metadata to understand the types, members, and references in an assembly, enabling features like reflection and versioning.

    Thread Management:
        The CLR provides support for multithreading, allowing applications to perform multiple operations concurrently. It manages thread creation, synchronization, and scheduling.

--Questions
-------------------

What is CLR (Common Language Runtime)?

✔ CLR is the engine of .NET that runs and manages your applications.
✔ It takes your C# or VB.NET code, compiles it into machine code, and executes it.
✔ Provides memory management, security, and exception handling.
✔ Helps run code written in different .NET languages together.

2. What is MSIL (Microsoft Intermediate Language)?

✔ When you write C# or VB.NET code, it doesn’t directly become machine code.
✔ Instead, it is first compiled into an intermediate language called MSIL (Microsoft Intermediate Language).
✔ This makes .NET cross-platform, as MSIL can run on Windows, Linux, and macOS when compiled by the CLR.

3. What is the use of JIT (Just-In-Time Compiler)?

✔ JIT Compiler is part of CLR that converts MSIL into native machine code at runtime.
✔ This allows .NET applications to be fast and optimized.
✔ It only compiles the code when needed, reducing load time and improving performance.

4. Who Reads Managed Code?

✔ Managed Code is code that runs inside the CLR (like C# or VB.NET).
✔ The CLR reads and executes Managed Code, taking care of security, memory, and performance.
✔ Unlike unmanaged languages (like C++), .NET automatically cleans up memory (Garbage Collection).

5. What is CLS (Common Language Specification)?

✔ CLS ensures that all .NET languages can work together smoothly.
✔ Defines a set of rules that all .NET languages must follow.
✔ Example: If a C# class is CLS-compliant, it can be used in VB.NET and F#.

6. What is CTS (Common Type System)?

✔ CTS standardizes data types across all .NET languages.
✔ Example:
    In C#: int
    In VB.NET: Integer

Both are treated as System.Int32 by CTS
✔ Ensures compatibility between different .NET languages.

7. What Should I Use for a Desktop Application?

✔  WinForms → For simple Windows applications.
✔  WPF (Windows Presentation Foundation) → For modern, rich UI applications.
✔  .NET MAUI → If you want to build for Windows, macOS, iOS, and Android in one codebase.

8. What Should I Use for a Web Application?

✔  ASP.NET Core MVC → For dynamic web applications.
✔  ASP.NET Core Web API → For backend services & APIs.
✔  Blazor → For web apps with C# instead of JavaScript.

9. What is WCF (Windows Communication Foundation)?

✔ WCF is a framework for building web services in .NET.
✔ Used for communication between applications, services, and systems.
✔ Supports multiple protocols like HTTP, TCP, and MSMQ.
✔ Use WCF when:
    You need secure SOAP-based web services.
    You require communication between different platforms (Windows & non-Windows).
    You need features like transaction support, message security, and queuing.
