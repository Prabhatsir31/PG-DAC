Design Pattern
-----------------
Design patterns are typical solutions to common problems in software design.
They are like pre-made blueprints that can be customized to solve a recurring design problem in your code.

Types of Design Patterns:
1. Creational Patterns (Singleton, Factory, Abstract Factory, Builder, Prototype)
2. Structural Patterns (Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy)
3. Behavioral Patterns (Observer, Strategy, Command, Iterator, Mediator, Memento, State, Visitor, etc.)

Example:
Singleton Pattern ensures a class has only one instance and provides a global point of access to it.


Static Content vs Dynamic Content
--------------------------------------------
Static Content:
- Delivered to user exactly as stored.
- Examples: HTML, CSS, JS, Images.
- Doesn’t change based on user interaction or input.
- Fast to load and cacheable.

Dynamic Content:
- Generated in real-time based on user input or backend logic.
- Examples: JSP, PHP, ASP.NET.
- Can display personalized data (e.g., user profiles, dashboards).
- Slower as it requires processing on the server.


Java-Enabled Web and Application Server
----------------------------------------------
- Web Server: Handles HTTP requests and responses (e.g., Apache HTTP Server).
- Application Server: Provides full support for building and running enterprise applications.
- Java-Enabled Application Servers support Java EE (Jakarta EE) technologies like Servlets, JSP, EJB, JPA, etc.

Examples:
1. Apache Tomcat – Web container (Servlet & JSP support).
2. GlassFish, JBoss/WildFly – Full Java EE support.


Web Container
----------------------
- A web container (also known as a servlet container) is part of a web server or application server.
- Manages the lifecycle of servlets and JSP.
- Provides support for HTTP protocol, security, concurrency, and deployment.

Examples:
- Apache Tomcat
- Jetty

Responsibilities:
- Loading, instantiating, and invoking servlets.
- Managing servlet context and configuration.
- Handling requests/responses.


EJB Container
--------------------
- Manages Enterprise Java Beans (EJBs).
- Provides services like transactions, security, concurrency, remote access, and lifecycle management.

Types of EJBs:
1. Session Beans (Stateless, Stateful, Singleton)
2. Message-Driven Beans (MDB)
3. Entity Beans (Replaced by JPA)

Examples:
- JBoss/WildFly, GlassFish

EJB Container Responsibilities:
- Dependency injection.
- Object pooling and lifecycle management.
- Security and transaction management.


SERVLET - ADVANCED JAVA COMPLETE NOTES
======================================

1. WHAT IS A SERVLET?
----------------------
- A Servlet is a Java programming class used to handle requests and generate responses in a web application.
- It runs on a web server or application server and is used to create dynamic web content.
- It works on the request-response model and is part of Java EE (Jakarta EE).

2. ADVANTAGES OF SERVLETS
---------------------------
- Platform Independent
- Better performance than CGI
- Robust and Scalable
- Can handle multiple requests simultaneously using multithreading
- Reusable and maintainable

3. LIFE CYCLE OF A SERVLET
---------------------------
The lifecycle is managed by the Servlet container (e.g., Apache Tomcat). It includes:

  a. Loading and Instantiation:
     - Servlet class is loaded and an instance is created.
  
  b. Initialization (init() method):
     - Called once when servlet is first loaded.

  c. Request Handling (service() method):
     - Called each time a request is made to the servlet.
     - It internally calls doGet(), doPost(), etc. based on the HTTP request.

  d. Destruction (destroy() method):
     - Called once before the servlet is removed from service.

4. SERVLET API INTERFACES
--------------------------
- javax.servlet.Servlet (interface)
- javax.servlet.ServletRequest
- javax.servlet.ServletResponse
- javax.servlet.http.HttpServlet (abstract class)

5. TYPES OF SERVLETS
----------------------
- GenericServlet: Protocol independent
- HttpServlet: Protocol dependent (HTTP), commonly used

6. METHODS IN HttpServlet
---------------------------
- init()
- service()
- doGet()
- doPost()
- doPut()
- doDelete()
- destroy()

7. BASIC SERVLET EXAMPLE
--------------------------
import java.io.*;
import javax.servlet.*;
import javax.servlet.http.*;

public class MyServlet extends HttpServlet {
    public void doGet(HttpServletRequest req, HttpServletResponse res) throws ServletException, IOException {
        res.setContentType("text/html");
        PrintWriter out = res.getWriter();
        out.println("<h1>Hello Servlet</h1>");
    }
}

8. WEB.XML CONFIGURATION
--------------------------
<web-app>
  <servlet>
    <servlet-name>MyServlet</servlet-name>
    <servlet-class>com.example.MyServlet</servlet-class>
  </servlet>
  <servlet-mapping>
    <servlet-name>MyServlet</servlet-name>
    <url-pattern>/hello</url-pattern>
  </servlet-mapping>
</web-app>

9. DEPLOYMENT STEPS
---------------------
1. Write the Servlet code
2. Compile and place the .class file inside WEB-INF/classes directory
3. Configure web.xml in WEB-INF folder
4. Deploy the project in Apache Tomcat webapps folder
5. Start the server and access: http://localhost:8080/YourAppName/hello

10. DIFFERENCE BETWEEN CGI AND SERVLET
---------------------------------------
- Servlet is platform-independent, CGI is not
- Servlet uses multithreading, CGI spawns a new process for each request
- Servlet is faster and more efficient

11. COMMON USES OF SERVLETS
-----------------------------
- Processing form data
- Dynamic content generation
- Session tracking
- Connecting to databases
- Creating REST APIs (in combination with frameworks)

12. TOOLS & SERVLET CONTAINERS
-------------------------------
- Apache Tomcat
- Jetty
- GlassFish
- Eclipse IDE (with servlet plugins)

13. HOW SERVLETS HANDLE CLIENT REQUESTS
----------------------------------------
- Client sends HTTP request to server
- Servlet container maps request to appropriate Servlet
- Servlet processes request using doGet/doPost etc.
- Generates response (usually HTML)
- Response sent back to the client (browser)
