.requestMatchers("/token").permitAll()

requestMatchers("/token"): This is saying that any HTTP request that matches the /token URL path should be handled in a special way.
permitAll(): This allows anyone (authenticated or unauthenticated users) to access the /token endpoint without any authentication or authorization checks. It's usually used for public endpoints (like login, registration, or token generation).

 .anyRequest().authenticated()
anyRequest(): This specifies that for all other HTTP requests (not matching /token), you need to define the access control rules.
authenticated(): This means that any request not matching /token must be made by an authenticated user. In other words, users need to log in (or have a valid session, token, etc.) to access any other endpoint.


	inside MySecurityConfig class we have created two beans:

a) SecurityFilterChain and
b) DaoAuthenticationProvider


what are these two beans i.e. SecurityFilterChain and DaoAuthenticationProvider used for?

Internally, Spring Security uses the securityFilterChain bean to configure the overall security settings for the web application. It automatically applies these rules to incoming HTTP requests when the application starts.

The daoAuthenticationProvider is part of the normal authentication flow when a user logs in using their credentials (username/password).
It verifies the credentials via the CustomUserDetailsService, which is responsible for fetching user details and authorities/roles from a database or other data sources.



Summary:-

securityFilterChain: Configures security and authentication settings for the application, including JWT token-based authentication (via jwtfilter) and rule-based access control (e.g., /token is public, others require authentication).

daoAuthenticationProvider: Responsible for authenticating users based on their credentials stored in a database, using the CustomUserDetailsService to load user details.
