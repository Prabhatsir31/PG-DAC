
### 1. **HTML Form (for Login)**

```html
<form id="loginForm">
    <label for="username">Username:</label>
    <input type="text" id="username" name="username">
    <br>
    <label for="password">Password:</label>
    <input type="password" id="password" name="password">
    <br>
    <button type="submit">Get Token</button>
</form>
```

- **Purpose**: This is the HTML form where the user enters their **username** and **password**.
- **Elements**:
  - `<input type="text" id="username" name="username">`: A text field for the username.
  - `<input type="password" id="password" name="password">`: A password field to securely enter the password (it hides the characters).
  - `<button type="submit">Get Token</button>`: A submit button that sends the form data to the server when clicked.

---

### 2. **JavaScript to Handle Form Submission**

```javascript
document.getElementById('loginForm').addEventListener('submit', function(e) {
    e.preventDefault(); // Prevent the default form submission
```

- **`addEventListener('submit', ...)`**: This code attaches an event listener to the form, so that when the form is submitted (when the user clicks the submit button), the specified function will be executed.
- **`e.preventDefault();`**: Normally, when a form is submitted, the page would reload and the form data would be sent to the server. By calling `e.preventDefault()`, we stop this default behavior and instead handle the submission via JavaScript (so that we can send the data via AJAX, without reloading the page).

---

### 3. **Get Form Data**

```javascript
var username = document.getElementById('username').value;
var password = document.getElementById('password').value;
```

- **`document.getElementById('username').value`**: This gets the **value** (the text entered) in the **username** input field.
- **`document.getElementById('password').value`**: This gets the **value** (the password entered) in the **password** input field.

Now you have the username and password values stored in the `username` and `password` variables.

---

### 4. **Prepare Data to Send with `fetch()`**

```javascript
const formData = new URLSearchParams();
formData.append('username', username);
formData.append('password', password);
```

- **`URLSearchParams`**: This is a special object used to build data in the format that can be sent as part of a URL or as form data (like `application/x-www-form-urlencoded`).
- **`formData.append()`**: This method adds the `username` and `password` to the `formData` object. It's like preparing the form data to send to the server.

Example: The `formData` now looks like:
```
username=someUser&password=somePassword
```

---

### 5. **Sending Data with `fetch()`**

```javascript
fetch('/token', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/x-www-form-urlencoded',
    },
    body: formData.toString() // Convert URLSearchParams to string
})
```

- **`fetch('/token', ...)`**: The `fetch()` function is used to send a **request** to the server. In this case, the request is being sent to the URL `/token` on your backend, which should correspond to a controller in your Spring Boot application that handles the `/token` route (i.e., it generates the JWT token).
  
- **`method: 'POST'`**: This tells the browser that you are sending data to the server using the **POST** method. POST is used when sending data that might change something on the server (like generating a JWT token).

- **`headers: { 'Content-Type': 'application/x-www-form-urlencoded' }`**: The `Content-Type` header specifies the type of data you're sending to the server. In this case, you're sending URL-encoded form data (the same format as a regular HTML form would use).

- **`body: formData.toString()`**: This is the actual data you're sending. `formData.toString()` converts the form data into a string like this:
  ```
  username=someUser&password=somePassword
  ```

---

### 6. **Handling the Response**

```javascript
.then(response => response.json())  // Parse the JSON response
```

- **`response.json()`**: Once the server responds to the request, the `.then()` method is called. The response is passed to the function, and `response.json()` is used to convert the response body (which is a JSON string) into a JavaScript object.

For example, if the server sends:
```json
{ "token": "eyJhbGciOiJIUzI1NiJ9..." }
```

This will be converted to a JavaScript object:
```javascript
{
    token: "eyJhbGciOiJIUzI1NiJ9..."
}
```

---

### 7. **Using the Token**

```javascript
.then(data => {
    console.log("JWT Token:", data);
    alert(data.token);  // Assuming the response contains a `token` key
    
    // Redirect to the welcome page with the token as a query parameter
    window.location.href = "/welcome?token=" + data.token;
    alert("Redirecting to welcome page...");
})
```

- **`data.token`**: This is the JWT token that you received from the server. The server response is expected to be a JSON object, and the token is extracted from `data.token`.
- **`console.log("JWT Token:", data)`**: Logs the entire response object to the browser console, so you can see what was returned from the server.
- **`alert(data.token)`**: Displays an alert showing the JWT token.
- **`window.location.href = "/welcome?token=" + data.token`**: This changes the browser's location to the `/welcome` page, **appending the token as a query parameter**. This redirects the user to the welcome page with the token included in the URL (e.g., `/welcome?token=eyJhb...`).

---

### 8. **Error Handling**

```javascript
.catch(error => {
    console.error('Error:', error);  // Log any errors
    alert('Error occurred: ' + error.message);
});
```

- **`.catch()`**: If there's any issue with the `fetch()` request (e.g., the server is down, or there's a network problem), the `catch()` block will execute.
- **`console.error('Error:', error)`**: Logs the error to the browser console.
- **`alert('Error occurred: ' + error.message)`**: Displays an alert with the error message.

---

### Recap:

1. **Form Submission**: When the form is submitted, the default form behavior is stopped using `e.preventDefault()`.
2. **Prepare Data**: The form data (username and password) is collected and converted into a format that can be sent to the server (`URLSearchParams`).
3. **Send Data**: The data is sent to the server using the `fetch()` API with the **POST** method.
4. **Handle Response**: The server responds with a JSON object containing the JWT token. The frontend then processes the response, logs the token, and redirects the user to the welcome page.
5. **Error Handling**: If something goes wrong, the error is caught and displayed.

### Key Concepts:
- **`fetch()`**: Used to make HTTP requests (like GET, POST) from JavaScript.
- **Promises**: `fetch()` returns a **Promise** that allows you to handle asynchronous operations (i.e., things that take time, like network requests).
- **Event Listeners**: Used to trigger functions in response to user actions, like form submissions.
